# 새로 초기화한 TLN 계열 모델과 직접 수집한 주행 데이터

지정 맵은 `stack_master/maps/hangar_1905_v0`다. 기존 `TLN_aug.keras` 및 이전 TLN 가중치는 이 모델의 초기화·학습에 사용하지 않았다. 최종 모델은 무작위 초기화 후 62회 학습한 `results/final_model.keras`다.

최종 시험에서 신경망 단독과 보호 제어 적용 결과를 분리했다. **일부 장애물 배치에서 충돌 또는 정지가 남아 있어, 요구한 주행 성능을 모두 달성한 상태는 아니다.** 수치와 실패 위치는 최종 보고서와 원본 평가 JSON에서 확인한다.

## 최종 파일

- `results/final_model.keras`: 선택한 새 모델. 입력은 `(541, 6)`과 42차원 벡터, 출력은 5개다.
- `results/training_v2.json`: 실제 최종 학습 이력, 초기 가중치 해시, 데이터 파일 및 해시, 검증 오차.
- `results/final_selection.json`: 검증 결과에 따른 모델 선택 근거.
- `results/evaluation_strict_final_test.json`: 한 바퀴 전체 길이 이상, 리셋 없이 수행한 최종 시험 궤적·명령·판정.
- `results/evaluation_strict_final_test_summary.json`: 최종 시험 요약.
- `data/`: 시뮬레이터를 직접 구동해 녹화한 원시 LiDAR·상태·명령 및 회차별 결과.
- `data/ros_fast/`: 실제 ROS bag에서 시간 정렬해 추출한 고속 기본 주행 학습 구간 2개.
- `data_v2/`: 위 새 데이터에 LiDAR 전경 특징과 전문가 조향 정답을 추가한 학습 입력.
- `recordings/basic_fast_2p2/`: 고속 기본 주행 원본 ROS bag.

## 모델 구조와 입력

기존 모델을 불러오지 않고 Conv1D 4개 층과 경로·상태 분기를 새로 만들었다. 총 파라미터는 189,773개다. 마지막 경로·조향 보정 출력은 0으로 초기화해 처음에는 기준 경로를 따르도록 했고, 나머지 신경망 가중치는 무작위로 초기화했다.

LiDAR는 1080개를 1081개로 보정한 뒤 2개마다 하나를 선택해 541개를 사용한다. 범위를 0~10 m로 제한해 0~1로 정규화한다. 3프레임 거리와 3프레임 전경 마스크를 합쳐 6채널을 구성한다.

42차원 벡터는 지역 레이스라인 8개 점과 경계 폭, 실제 속도, 이전 조향 명령, 관측 장애물 후보의 상대 위치·거리·좌우 여유를 포함한다. 전경 마스크와 장애물 후보는 LiDAR 반사점, 정적 지도, 현재 위치로 계산한다. 추론 시 시뮬레이터의 장애물 정답 좌표를 입력하지 않는다.

따라서 이 모델은 원래의 LiDAR 단독 모델과 다른 **지도·지역 경로를 사용하는 TLN 계열 새 모델**이다. 시뮬레이션 시험은 GT odometry를 사용했으며 PF 오차가 있는 조건과 다른 맵에서는 별도 시험이 필요하다.

## 전문가와 데이터

`expert.py`는 가상 경로 진행률, contour/lag 오차, 자전거 모델, 경계·장애물 제약을 사용하는 MPCC다. 장애물별 통과 공간을 비교하고, 곡선·장애물 접근 속도를 조절한다. 신경망이 아닌 MPCC 알고리즘 코드를 사용한 것이며, 기존 TLN 가중치를 전문가로 사용하지 않았다.

기본 주행은 레이스라인 피드백 제어기로, 회피·MPCC 주행은 최적화 전문가로 새로 수집했다. 각 회차의 원시 스캔, 상태, 명령, 배치와 충돌 판정을 저장했다. 원래 학습 후보 32회 중 완주한 31회와 실제 고속 기본 주행 ROS 녹화의 완주 구간 2개를 최종 모델 학습에 사용했다. 검증 8회 중 전문가가 완주한 6회만 회귀 오차 계산에 사용했지만, 폐루프 시험에는 실패한 배치도 포함했다.

학습·검증·시험은 배치 시드 단위로 분리했다. 같은 맵의 조건 비교이며 다른 맵으로의 일반화 시험은 아니다. 기본 주행의 반복 두 회는 같은 시작 조건이므로 독립적인 두 지도 시험으로 해석하지 않는다.

## 출력과 제어

출력 0~2는 앞쪽 0.75, 1.5, 2.5 m 지점의 보조 경로 보정량이다. 각각 0.9 m를 곱해 복원한다. 출력 3은 목표 속도이며 2.8 m/s를 곱한다. 출력 4는 MPCC 조향의 보정량이며 0.72 rad를 곱한다.

실제 조향은 레이스라인 기준 조향에 학습 보정을 더한 뒤 ±0.36 rad로 제한한다. 속도에는 곡률에 따른 상한을 적용하고 정지를 허용한다. 기존의 3 m/s 최저속도, EMA와 예전 속도 후처리는 사용하지 않는다.

보호 제어는 별도의 기하학적 경로 검사·조향 보정·제동 기능이다. LiDAR와 지도 기반 전경 정보만 사용한다. 보호 제어로 얻은 성능을 신경망 단독 성능이라고 보고하지 않는다. 정지해 충돌을 피했더라도 완주 실패로 집계한다.

## 재현 환경

ROS2 Humble 및 이 ForzaETH 워크스페이스의 F1TENTH 시뮬레이터가 필요하다. 패키지는 워크스페이스의 `experiments/tln_fresh` 위치에 놓는다. 맵과 차량 설정의 해시가 제공된 값과 같은지 확인한다.

```bash
source /opt/ros/humble/setup.bash
source install/setup.bash
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=2 python3 experiments/tln_fresh/evaluate_strict.py --split test --model final_model.keras --tag _reproduced
```

신경망 단독과 보호 제어를 모두 시험한다. 단위는 시뮬레이터의 고정 시간 간격 기준이다. 실제 경과 시간으로 측정하는 ROS race_manager 랩타임과 직접 섞어 비교하지 않는다.

새 학습은 `train_v2.py`를 사용한다. `--dataset-manifest results/training_v2.json --output-dir results/reproduction` 옵션으로 실제 최종 학습에 사용한 데이터 목록을 고정하고 결과를 별도 폴더에 저장할 수 있다. 같은 데이터라도 하드웨어·라이브러리에 따라 수치가 조금 달라질 수 있다.

실시간 실험용 명령은 다음과 같다. 기존 `/drive` 발행기와 동시 실행하지 않는다.

```bash
python3 experiments/tln_fresh/live.py --mode student --model experiments/tln_fresh/results/final_model.keras
```

현재 화면에서 실행한 고속 기본 주행은 `--mode basic --cruise 2.2`이며 신경망 회피 시험과 구분한다. 최종 모델의 실시간 ROS 장애물 완주 성능은 아직 확정하지 않았다.

## 시간·복구·평가 해석

최종 엄격 시험은 기록된 경로 길이 55.2902 m 이상을 이동하고 충돌하지 않아야 성공이다. 초기의 길이에서 0.5 m를 뺀 허용 기준 시험과 구분해 파일 이름에 `strict`를 붙였다. 성공 랩타임 평균에는 완주한 회차만 들어가므로 완주 횟수를 반드시 함께 읽어야 한다.

실시간 물리 계산 주기와 실제 경과 시간이 다를 수 있다. 라이브 코드에는 odometry로 진행 시간을 추정하는 보정이 있지만, 이는 ROS `/clock`을 사용하는 정확한 동기화와 같지 않다. 오프라인 성능을 그대로 화면 주행 성능으로 해석하지 않는다.

복구나 pose 변경은 성공 주행이 아니다. ROS bag의 충돌·리셋 구간은 정상 학습 구간에서 제외했다. 초기 실패 녹화와 선택하지 않은 모델의 결과도 진단 자료로 분리해 보존했다.
